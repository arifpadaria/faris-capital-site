# Faris Capital website audit

Date: 2026-09-08 (ET). Baseline commit: `cf19c2c`.
Scope: local source and publishing workflow, public HTTP responses, desktop Chrome and responsive Chrome viewports. Website: https://faris-capital.com/.

**Implementation update (2026-09-09):** Publishing validation, security headers, explicit public-output packaging and mobile fixes are implemented and tested locally. See [implementation checkpoint](IMPLEMENTATION_CHECKPOINT.md) and [verification record](VERIFICATION_2026-09-09.md). Findings below describe the original audit baseline; the live website has not been redeployed.

## Assessment

The site has a credible visual foundation: restrained navy and gold, an editorial typeface, clear audience categories, substantive partner biographies, and a useful collection of original writing. Keep that identity and the lightweight static architecture.

The highest-priority work is the local publishing pipeline and mobile navigation. The public site has HTTPS and several good SEO foundations, but lacks important browser security headers. Its deployment boundary includes development material. The strongest commercial story, the partners' operating experience and cross-border execution, is clearer on About than on the homepage.

This audit created documentation only. Application source, hosting settings, credentials, and the live deployment were not changed. No forms or messages were submitted. Recommendations below are proposed, not implemented.

## Findings, ordered by priority

### 1. High: article titles reach a shell command

Evidence: `scripts/publish.js:393` and `scripts/add-perspective.js:176` construct a double-quoted shell command from the article title, escaping only double quotes. Shell command substitution still works inside that argument.

A harmless isolated reproduction using the same argument construction changed the literal title `Example $(printf AUDIT_MARKER)` into `Example AUDIT_MARKER`. No Git operation, deployment, or external command payload was executed in this test.

Impact: copied text used as a title can execute commands with the publisher's local permissions when the operator selects deployment. This is a local publishing vulnerability, not an unauthenticated remote website endpoint.

Fix: use `execFileSync` or `spawnSync` with separate arguments and no shell. Scope staging to intended files instead of `git add .`. Do not place credential values in shell strings. Add tests for dollar signs, backticks, quotes, and newlines. Node's [child-process documentation](https://nodejs.org/api/child_process.html) specifically warns against passing unsanitized input to a shell.

### 2. High: article body is executable data; HTML is not safely handled

Evidence: `scripts/publish.js:312` and `scripts/add-perspective.js:139` place the formatted article body directly inside a JavaScript template literal. `scripts/generate-thesis-pages.js:26` evaluates the generated file using `vm.runInContext`. The browser also loads this data file on the homepage and Perspectives index.

An in-memory reproduction using the publisher's actual `formatContent` function and the generated template-literal structure confirmed that the benign input `${globalThis.auditMarker = 7}` executes during evaluation. Literal backticks can also break the generated JavaScript. `formatContent` wraps text in paragraph tags without escaping HTML. Teasers are interpolated into HTML in the generator and browser grids; the full article body is emitted as HTML. LinkedIn URLs are attribute-escaped but not restricted by scheme or hostname.

Impact: ordinary code examples can break publishing; malicious pasted content can inject behavior into the generation process or published pages. An operator must import/publish the content. The test did not attempt a Node sandbox escape or execute a browser attack. Node states that [the VM module is not a security boundary](https://nodejs.org/api/vm.html).

Fix: store structured content as JSON, validate records and unique slugs before writing, and parse rather than evaluate data. Escape plain text before producing HTML. If rich HTML is deliberately supported, use an explicit sanitization policy that preserves the existing articles' formatting. Restrict external article links to approved HTTPS destinations. Validate in temporary output before replacing live source files.

### 3. High usability priority: small-phone navigation is clipped

Evidence: at a requested 320 CSS-pixel viewport, Chrome's vertical scrollbar left a 305-pixel document area. The menu button's right edge was 327.70 pixels, so part of the control and icon were clipped. The screenshot confirmed this. Root cause: `.site-header .header-container.container` retains 48-pixel side padding, `.header-container` has a 50-pixel gap, and the logo cannot shrink. `overflow-x: hidden` conceals overflow instead of resolving it.

At 390 pixels the button fits. The homepage heading wraps into four lines, and content has generous nested horizontal gutters. On a fresh load the eyebrow begins at y=80 with a header ending at y=72, leaving only eight pixels of breathing room.

Fix: define one responsive header layout with a shrinkable logo, smaller narrow-screen gutters and gap, and a fully visible minimum 44-by-44-pixel menu target. Use consistent content gutters and measured spacing below the fixed header. Test both 320 and 390 pixels, larger phones, tablets, rotation, and browser zoom.

### 4. Medium: mobile menu and filters have accessibility defects

Evidence: the closed mobile navigation is moved offscreen using a transform but remains in the accessibility tree on desktop and mobile. Its button has no `aria-expanded` or `aria-controls`. Escape leaves the menu open. `js/main.js:18` onward has only a click toggle.

On Perspectives, choosing Physical AI correctly displayed ten cards, but rebuilding the filter buttons moved keyboard focus to `BODY`. Buttons have no `aria-pressed` state. Repeated link labels such as “Read Perspective” also offer limited context when read separately.

Fix: implement navigation as an accessible disclosure; make closed links noninteractive and absent from the accessibility tree, announce open state, close on Escape, restore focus, and handle viewport changes. Keep filter controls stable, expose their selection state and a result count, and preserve keyboard focus. Add a skip link and contextual article-link names. Follow the [W3C disclosure pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/).

Positive: the What We Do tabs already expose tab/panel semantics, load the `#capital` deep link correctly, and support ArrowRight navigation. Preserve that behavior.

### 5. Medium: hosting lacks browser hardening headers

Evidence: the homepage, About, Contact, What We Do, Perspectives, CSS and main JavaScript responses were inspected. They include HSTS but no Content-Security-Policy, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, or Permissions-Policy. The Firebase source defines cache headers only.

Fix: add `X-Content-Type-Options: nosniff`, a deliberate referrer policy, framing restrictions, and a permissions policy for unused capabilities. Build and test a Content Security Policy with narrowly scoped resource origins. Preserve Google Fonts if retained. The homepage, filters, service tabs, legacy redirect, and structured metadata use inline scripts, so a blanket `script-src 'self'` would break functionality. Externalize executable inline scripts or generate maintained hashes and validate in report-only mode before enforcing. Existing inline styles need an explicit compatibility decision.

Missing headers are defense-in-depth gaps; they alone do not prove a compromise. See [Firebase header configuration](https://firebase.google.com/docs/hosting/full-config?hl=en) and [MDN CSP implementation guidance](https://developer.mozilla.org/en-US/docs/Web/Security/Practical_implementation_guides/CSP).

### 6. Medium: development and public deployment share one root

Evidence: `firebase.json` sets `public` to `.`. It excludes Markdown, scripts, dotfiles and some other folders, but not the entire `medium-export` staging directory. A GET to `/medium-export/2026-08-16-one-line-in-sahil-bhaiwalas-data-thesis-points-at-the-next-100b-question-cover.png` returned 200 and matched the local 272,060-byte image. Nineteen PNGs currently reside in that staging folder. One was checked live; public availability of all nineteen was not tested.

The staging images appear to be article artwork, not credentials; this is a confirmed deployment-boundary issue, not evidence of secret leakage. `/business-card-single.html` is also public, which may be intentional and should be decided explicitly.

Fix: exclude `medium-export/**` immediately in the proposed patch. Prefer a generated `dist/` directory containing an allowlist of actual public pages and assets. Assert the output manifest before deploy. `.gitignore` does not control Firebase's direct local uploads. [Firebase documents](https://firebase.google.com/docs/hosting/full-config?hl=en) the separate `public` and `ignore` controls.

### 7. Medium: deployments can race, include unrelated work, and fail unclearly

Evidence: both publishers push to `main` and then deploy directly. `.github/workflows/deploy.yml` also deploys on a push to `main`. The workflow installs the latest Firebase CLI without a version lock and has no build/test gate, explicit job permissions, or deployment concurrency control. `publish.js:408` catches an exception as `error`, shadowing its `error()` logger, so reporting a failed deployment itself throws. The older add-perspective script does not regenerate static thesis pages before deploying.

Fix: choose one production deployment path, add a preview/check stage, pin tool versions, narrowly scope GitHub permissions, and serialize deployments. Add an explicit output manifest and validation for article generation, duplicate IDs, sitemap consistency, and failed commands. Preserve a known-good release for rollback. Treat replacement of the older publisher as a workflow decision.

The current workflow and local publisher use Firebase user tokens. Firebase labels this [authentication method deprecated](https://github.com/firebase/firebase-tools/blob/main/README.md). Plan a scoped supported identity flow, ideally short-lived CI credentials where supported. Account permissions, branch protection, token scope, and credential age were not inspected. No credentials were changed.

### 8. Medium: mobile article cards and gold text need refinement

Evidence: at 320 pixels, two “Venture & Capital Strategy” labels extended beyond the document's right edge. Their row does not wrap and the label uses `white-space: nowrap`. The 20-card listing measured about 14,502 pixels high at this width. Several teasers are long paragraphs rather than compact summaries.

The CSS defines small gold article dates as `#C5A059` on white, a calculated 2.46:1 contrast ratio; small partner-role text uses `#D4AF37`, 2.10:1. Both are below the 4.5:1 minimum for normal-size text. See [W3C contrast requirements](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum).

Fix: let metadata wrap or stack, shorten card excerpts while preserving complete articles, and use navy or a darker accessible gold for text. Keep the lighter gold for decoration. Keep an efficient route to themes and offer a modest pagination/load-more treatment if the library grows.

### 9. Medium: improve resilience and motion behavior

Evidence: headers, footers, homepage article cards, and the Perspectives list depend on JavaScript injection. The initial homepage HTML contains zero values for two animated metrics. `main.js` applies invisible fade classes until IntersectionObserver triggers. There is no reduced-motion preference handling. Full-page screenshots taken without scrolling show unobserved biography blocks as blank; this does not mean those blocks are permanently missing during normal scrolling.

Fix: generate shared navigation, key content and final metric values into static HTML, then progressively enhance. Animate individual bounded elements instead of large containers; keep content visible if animation setup fails. Respect `prefers-reduced-motion`. This also allows a stronger CSP without depending on fragile inline scripts.

### 10. Medium performance opportunity: oversized portrait and unnecessary content payload

Evidence: Arif's PNG is 1,439,548 bytes with a 912-pixel natural width, displayed as an 84-pixel circle. Stephanie's image is 22,476 bytes. The homepage and Perspectives index both fetch the 106,168-byte uncompressed thesis data file containing full article bodies, although they display only card metadata. The CSS is 26,083 bytes and main JS 4,471 bytes, so a framework migration is unnecessary for the measured payloads.

Fix: supply a well-compressed portrait at roughly 168-252 pixels for high-density displays, using WebP/AVIF with a fallback and explicit dimensions. Load below-fold photos lazily. Generate a small card index or render cards statically. Consider self-hosting only the used font weights after checking licensing and measuring the benefit.

These are byte-size findings, not measured LCP, INP, CLS or Lighthouse scores. Larger unused image files exist in the repository, but their disk size is not evidence that visitors download them.

### 11. Commercial enhancement: make the operating advantage obvious sooner

The homepage's “Scaling Ventures. Aligning Capital.” headline is appropriate but broad. About makes the distinction clearer: experienced operators and investors with Boston/Dubai coverage who also execute the partnerships they structure.

Proposed hierarchy: hero and clear audience fit; a concise partner-experience strip; three outcome-oriented service routes; how an engagement works; a small set of selected perspectives; contact. Currently the long Latest Thinking section appears before the numerical experience proof.

Suggested hero supporting-copy direction, grounded in existing public wording: “We help growth-stage technology companies align capital, build strategic partnerships, and expand across the US, Europe, the GCC, and India. Operators first, advisors second.” Treat this as a draft, not approved copy.

Distinguish partners' prior career experience from Faris Capital's own mandates, especially around investment totals and returns. Add approved examples of challenge, role, and outcome, using anonymized cases where needed. Do not invent clients, endorsements, results, response-time promises, or publicize internal counterparties. Preserve the relationship/referral character of the contact page. Audience-specific email subjects and optional inquiry guidance can improve lead quality without introducing a backend form.

### 12. Low: editorial and layout consistency

Use “Perspectives” consistently instead of mixing it with “Theses.” The list assumes newest-first array order, but “Memory Is the Moat” dated May 22 appears below April entries. Sort by an explicit publication date and preserve the intended chronology when adding older writing.

On desktop, secondary-page headings, service grids and header content use different horizontal origins. `.section` and `.hero` override `.container` padding when combined on one element; some page sections add further inline overrides. Consolidate the spacing rules while preserving the visual identity. Improve article navigation with related perspectives and a restrained contact route. Per-article social images are optional, after the functional work.

Responsive Chrome is not a substitute for actual iOS Safari and Android Chrome. Those physical-device checks, Safari/Firefox/Edge coverage, touch/rotation/safe-area behavior, screen-reader testing, lab/field performance metrics and a full WCAG audit remain part of implementation acceptance. The credential scan was limited, not an exhaustive secret-history or account audit. No authenticated Firebase/GitHub console inspection or invasive penetration testing was performed. Python's separate TLS trust store failed initially; curl and Chrome succeeded without disabling certificate verification, so the Python error was not classified as a website TLS defect.

## Proposed implementation sequence

1. **Publishing and deployment safety:** replace shell interpolation, serialize/validate content safely, constrain HTML and URLs, fix error handling, bound deployment output, establish one deploy route, and prepare compatible security headers.
2. **Desktop/mobile reliability:** responsive header/gutters, accessible disclosure and filters, metadata wrapping, contrast, reduced motion, static essential content, portrait optimization. Preserve existing routes and redirects.
3. **Commercial polish:** clarify homepage positioning and experience attribution, rebalance content order, add approved outcome examples, refine contact guidance and article discovery.

Acceptance before production: local/preview checks for all 25 canonical pages and redirects; no unintended deployment files; title/content injection regression tests; CSP-compatible scripts, fonts and metadata; 320/390/430/768/1024/1440 px and 200% zoom checks; keyboard/escape/filter focus; reduced motion and JavaScript-disabled essentials; iOS Safari and Android Chrome smoke tests; measured performance baseline and comparison. After deployment, verify live headers, content versions, intended asset exclusions and navigation, with a rollback release available.
